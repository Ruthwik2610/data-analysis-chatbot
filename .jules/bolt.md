## 2024-10-24 - [React Token Streaming Stale Closures & O(N) Re-renders]
**Learning:** During token-by-token streaming updates to a large `messages` state in React, using inline functions for callbacks passed to list items (e.g., `onChoose={(v) => onPendingChoice(msg.id, v)}`) combined with missing memoization causes an O(N) re-render of every single chat bubble on every single token received. Furthermore, putting `messages` into the dependency array of a `useCallback` that is passed down to children causes the callback to break memoization on every token.
**Action:** Use a `messagesRef` updated via a `useEffect` hook to hold the latest `messages` state. This provides a stable callback reference for handlers like `handlePendingChoice` (because `messages` can be removed from its dependency array and `messagesRef.current` can be used instead). Then, wrap the list item component (`Bubble`) in `React.memo` and pass the stable callback directly as a prop (e.g., `onChoose={onPendingChoice}`) and handle the item-specific IDs internally. This drops the re-render cost from O(N) to O(1) per token update.
